## Tokens + units
- Every design value lives in `src/assets/styles/01-settings/_tokens.less` as a `:root` custom property. Custom CSS uses `var(--…)` only; **no px anywhere** (rem, em, %, vw). The 8px scale (`--space-*`) drives mobile and tablet rhythm; at the design width components use the exact Figma value in rem with the px figure in a trailing comment (`5.3125rem; // 85`). Component-specific Figma measures are declared as local custom properties at the top of the block, with the px value in a trailing comment.
- Bootstrap is themed only through `--bs-*` in `_bootstrap-vars.less`; buttons through `--bs-btn-*` in `05-components/_buttons.less`.
- **The root font-size is a px table per breakpoint**, in `html` in `03-base/_base.less` — the one place px is allowed, because every rem resolves against it. Nothing else in the project may use px. 16 holds from 0 to the 1640 design width and is load-bearing there: the Figma audit at 1640, the 44 tap targets (`2.75rem`), the 16 form controls and the 12 text floor are all rem and verified at 16, so changing any value up to 1640 breaks them. Above it the root is `calc(100vw / 102.5)` (16 at 1640, 18.7 at 1920, 25 at 2560), so a wide screen shows the 1640 frame scaled to fit, as Figma shows it zoomed to fit; the client compares the two side by side at 1920. A px root ignores the reader's own browser font setting (browser zoom still works); switching the table to `%` — `100%` for 16, `112.5%` for 18, `131.25%` for 21, `150%` for 24 — renders identically and restores that. After any change here, re-run the Figma audit and `mobile-audit.mjs`: both must be unchanged, because both only ever see 16.
- **Escape fluid maths from LESS**: `~"clamp(1rem, 0.5rem + 2vw, 3rem)"`, `~"max(…)"`, `~"min(…)"`. Unescaped, LESS adds rem + vw into a wrong constant.
- Breakpoints are the LESS vars `@bp-sm … @bp-xxl` (px, matching Bootstrap's grid exactly), mobile-first `min-width` queries. `@upto-lg`, `@upto-md` and `@upto-xxl` are the `max-width` twins for redraws and for Figma measures that only exist at the design width; `@bp-design` (1640) is the frame itself.
- **A fixed Figma measure must still fit a 992 screen.** Where a value only works with the whole 1640 frame, it scales down with `clamp()` and returns to the exact Figma value by 1640 (the header logo, nav gap and link size from 992 to 1200; the pillar and link-column paddings), or the column caps it with container units (`container-type: inline-size` on the item, then `min(…, 20cqw)` for the pillar statement and `calc(100cqw * 475 / 302)` for the news card's height). Never a fixed height where copy can grow: the mosaic rows follow their photos' aspect ratios and the cards stretch, so a long paragraph on a narrow laptop grows the row instead of spilling out.
- Headings wrap naturally (no `text-wrap: balance`): Figma's line breaks are greedy.

## Markup
- `h1`–`h6` carry **no classes**; style through the parent block (`.pillars h3`, `.site-footer h2`).
- One section = one partial in `src/sections/` with a `@wagtail-block` comment. Shared, parametrised blocks take `locals='{…}'` (JSON in a single-quoted attribute: use typographic apostrophes, escape inner double quotes). Every local a partial reads must be passed, even as `""`. Page-specific list content lives in `src/sections/<page>/`.
- Icons are `<symbol>`s in `partials/icons.html`, used via `<svg class="icon"><use href="#icon-name">`, coloured by `currentColor`. The diagonal arrow symbol is 32 wide; list arrows carry `margin-right: -0.375rem` to land where Figma's 26 frame does.
- Images: WebP under `src/assets/images/<page>/`, always with `width`/`height` attributes and alt text.
- Animation only via `data-anim-*` (loops use `data-anim-group` on the parent). Reveal animations leave an inline `opacity` on the element, so state styles that touch opacity go on a child. `data-anim="sequence"` plays one staggered timeline over its `data-anim-item` descendants (the header drop, the hero quick links, the approach tabs and hotspots) and clears their inline styles when done, so those items keep their own hover transitions; an item may name its own preset (`data-anim-item="fade-up"` on the open hotspot card, which fades up on click too: the user did not want its clip wipe). Rich text cannot mark its paragraphs, so a sequence wrapping CMS output takes `data-anim-items="children"` and its direct children become the items (the hero intro body). Sequences may nest: an item belongs to its nearest sequence ancestor (the phone accordion rows slide in from the right as one staggered sequence on `.tab-content`, around the hotspot sequences inside each pane; on desktop the rows are hidden, so that sequence has no items and does nothing). A sequence whose items sit side by side only on desktop takes `data-anim-mobile="each"` so each item reveals on its own where they stack (the pillar statements, the hero intro paragraphs — there with `data-anim-stagger="0"`, so on desktop they still enter together as one block); `data-anim-disable-mobile` skips it entirely (the hotspots). A reveal with `data-anim-media="<query>"` only runs where the query matches at load and simply shows elsewhere (the quote slider's copy fades up on phones only: from md it sits in the hover box, whose parked position below the photo would hold the fade back and open the box empty). Scroll reveals are tied to the scroll but only move forwards: each starts when the element's top reaches 85% of the viewport and completes over the next 28% of the viewport height (`SCRUB` in `anim.js`), trailing the scroll by 0.4s, and never reverses, so a fast scroll never outruns the content (`data-anim-scroll="timed"` keeps a step on the clock instead: the testimonial and educator slider wipes); `data-anim-start` overrides the start line in ScrollTrigger syntax for tall blocks whose pieces sit low (the hotspots use `top 45%`). A scroll reveal already in view at load follows the page entrance as its last step (it starts `entranceLead` before the entrance ends), so a short hero such as the news article's never lets the copy below beat the title. Its trigger stays alive while it waits, so a reader who scrolls down before the entrance is over sees it follow the scroll at once, not a blank section. On phones a scroll step also waits for its section title, the nearest split before it in the same `main > *` block, so copy never beats its heading; the home page opts out with `data-anim-titles-first="off"` on `<main>` because its 375 frame is choreographed per block. `data-anim-tier="hero"` is the page entrance: one timeline on load, stepping through `data-anim-order` (header 0, title 1, then the rest), each step starting 0.4s before the previous one ends unless `data-anim-lead` says otherwise; `data-anim-order-mobile` replaces the order below 992 where the phone layout stacks things differently (the home quick links enter right after the title there, before the intro copy), and `data-anim-type-mobile` / `data-anim-stagger-mobile` / `data-anim-lead-mobile` replace a step's preset, stagger and lead there (below lg the quick links rise 14 and fade in left to right, `rise-soft` 0.08 apart, starting 0.7s before the title's step ends so they come in while its last letters are still rising (0.25 and 0.5 read as a pause, 2026-10-06), and the content under the hero waits for them; from lg they enter from the right as a docked strip). A title is split with one read and one write pass, and one already on screen is split before the entrance starts: a read after each write is a layout per letter, which froze phones mid-animation. Scroll-scrubbed steps (`data-anim="progress"`, or a reveal with `data-anim-scrub`) likewise take `data-anim-start-mobile`, `data-anim-end-mobile` and `data-anim-scrub-mobile` twins (the day-in-the-life steps scrub at 1.5 on desktop and 0.5 on phones, so they track the spine, which scrubs at 0.5). A scrubbed reveal triggers from its nearest `data-anim-trigger` ancestor, or else its parent, because its own box has already been moved by the preset's start state: give it an untransformed slot of its own (the Mina Wylie photo) or the trigger is wherever the parent happens to be, which on phones can be a whole section above it. Hero titles are `data-anim="split" data-anim-type="chars"` (soft letters, picked in `.qa/title-lab` on 2026-10-05: each character fades in over 0.85s, 22ms apart with the run capped at 0.56s, and lifts 0.12em — 16 at the 131.6 desktop title, 7 at the 60 phone title) and section titles are `chars-soft` (0.2em: 7 at the 35 h2, 0.62s, 15ms apart, the whole run capped at 0.375s); both revert to the original markup when done, so kerning is exact at rest. The lift has its own short run (`lift`: 0.4s and 0.3s, `power1.out`), so it lands while the letter is still fading in: text is drawn on whole pixels, and a lift eased as slowly as the fade arrives as separate 1px hops after the letter already looks still. `will-change` on the letters only cures that at 100% display scaling and makes the ending worse at 125%, so it is not used. The entrance waits for `document.fonts.ready` (800ms cap) so a split never measures the fallback face, and the split's boxes reset `text-indent` (the hero's indented line) so they do not indent again. The build-time search index gives headings without an `id` a slug, so a result can deep-link to its section. Banner photos use `.parallax-media(@travel)`; the inner hero uses the spare image Figma has below the frame (exact at rest).
- **Ruled rows all enter the same way**: every single-column list of ruled rows (the CTA links, K-6 academic excellence, the fees and strategy links, the home approach rows on phones) gives each row `data-anim="reveal" data-anim-type="nudge-right"` on the element that carries its rule, never a group or sequence on the list: each row slides 40 in from the right and fades up, rule and all, as its own top reaches 85% of the screen, so side-by-side cells arrive together as a row. `_animation.less` gives those rows `will-change: transform, opacity`, keeping them on one layer before, during and after the slide; without it Chrome drops the layer as the fade ends and the 1px rule visibly snaps sharper. The approach rows are the one exception (`:not(.approach__row)`): a composited row beside a pane that folds under it, instead of around it as in the CTA links, made the switch between panes shiver on iPhone Safari and left a rule hidden afterwards (2026-10-06). **Cards and columns all enter like the staff grid**: `data-anim-group="fade-up"` on the list, so each card rises 15 and fades in, staggered along its row (the staff grid, news cards, the teams and Preparatory columns, the extra-curricular activity cards, the dispositions and policy grids, the K-6 mosaic tiles). A group child that is `display: contents` has no box, so its own children become the items (the mosaic's slides from lg, where each tile is a grid cell). The user asked for that one subtle entrance on every card section on 2026-10-05; the ruled ones keep the same `will-change`. The home approach rows reach it through `data-anim-mobile="each"` with `data-anim-item="nudge-right"` on each row button.
- Page transition (`06-animation/_page-transition.less`: cross-document view transitions, `@view-transition { navigation: auto }`): the next page slides up over the page being left, which settles back and dims beneath it; a back step reverses it (the head script tags the transition `back` from `navigation.activation` on `pagereveal`). The old and new roots keep `mix-blend-mode: normal`, or the overlap washes out. The hero entrance is untouched but waits for the slide to land: the head script stores the transition's `finished` promise as `window.__pageArrival` (null at the first frame when there is none) and `Anim.init({ after })` holds the entrance on it, capped at 2s. `scripts/transition.js` only prefetches a page link on hover, focus or touch so the slide can start on the click. A browser without cross-document view transitions, and reduced motion, load as before; in-page jumps never transition, and neither does a `file://` preview (opaque origin), so shoot it over http.
- **Hovers stay plain** (client, 2026-10-05: less is more, it should feel like an expensive grammar school): the header links only turn yellow (the current page stays yellow), every button, arrow and tab only fades colour, the map does not zoom and the policy titles carry no underline. The page-load entrances and the page transition were approved as they are.
- No inline styles. Data-driven positions (hotspots) use modifier classes that set `--x` / `--y`.
- Heading-left / copy-right rows are `row g-4 row-split` with two `col-lg-6`: Figma butts the two 620 columns together and lets the heading's own box leave the air, which only holds once the columns reach 620 at xxl, so `.row-split` keeps a 40 gutter up to 1300 and closes it to 0 by 1400 (`_bootstrap-vars.less`). Never `g-lg-0` on its own. A designed `<br>` in a heading that needs the whole 620 box is hidden with `@upto-xxl` (the news lead), and from lg to xxl that heading stops 40 short of its column so its lines never run up against the copy. A split title's own line breaks are `<br>`s with an inline `display`, so a rule that hides a heading's designed `<br>` cannot collapse the title onto one line while it animates.
- Carousels that need real slider behaviour are Swiper (bundled from npm, core CSS inlined in `main.less`): a `data-slider` section holds a `.swiper` with `data-slider-start`, and its own `data-slider-prev/next` arrows (`scripts/slider.js`). Slides snap to the `.container` edge like the native scrollers (`data-slider-edge`, or `data-slider-edge="md"` to run full-bleed on phones and snap from tablets). `data-slider-below-lg` on the section builds the Swiper only below lg and tears it down above, so one list of items (one CMS block) is a CSS grid on desktop and a slider on phones (the pillars: `data-slider-per-view="1"`, arrows disabled at the ends); `data-slider-per-view-md="2"` shows two slides from md (the executives and the mosaic pairs on tablets).
- The home testimonials and the welcome educators are one block, `sections/quote-slider.html` + `_quote-slider.less`: the page files are thin wrappers passing `layout` (`testimonials` | `educators`, which only sets that Figma frame's card size and spacing), the title, an optional intro and the slides, each with an optional `author` / `role` and an optional `url` (the photo then links and shows the diagonal arrow). On phones each photo drifts in a little behind its card's edge (`data-slider-parallax="35%"`: Swiper's Parallax module, phones only and off under reduced motion; the photo trails the card by 35% of its width, which stays under the card's own travel so its box never shows a gap, and it rides the slide's `--ease-out`), and the arriving card's quote and author rise line by line out of masks from 0.1s in (`data-slider-lines="[data-quote-text]"`, `scripts/slide-lines.js`: SplitText lines, the mask clipping a box taller than the 0.95 line box so the display face's descenders are never cut; the touch rise on `.is-open` stands down while it runs and stays as the reduced-motion fade). ## QA
- **Never build a section from a guess.** Read its Figma nodes first (`python .qa/find.py <page-id> "<text>"` shows a text's box, style and parent frames; `.qa/extract.py <page-id>` dumps a page).
- `bash .qa/audit.sh summary|full [page …]` builds, measures each page at 1640 (`measure.mjs`) and compares with Figma (`compare.py` for sections + text runs, `compare-img.py` for photo boxes). A change is done when the page shows no `<<<` section flags and no text run off by more than ~3px. Expected noise: the two logos (Figma frame is wider than the artwork), `weight 400 vs 100` (Figma records the Argent CF Thin face as 100/250; the CSS asks for 400 and the `@font-face` range maps it onto Thin — the rendered face is correct), labels joined by `<br>`, primary button labels (Figma overrides their characters to Inter on every primary but the home hero, and sets six of them Near Black and one Dark Green; the build keeps the component's Instrument Sans and one Green label on every button), and runs where Figma's own boxes disagree — the hero's x values (h1 198 / subtitle 201 / body 200) and the preparatory 4-up label row whose gaps are 406/416/406 against an even 410. `compare.py` matches a Figma text node to the widest measured run, so a node split across a wrapper and an inner span (enrolment's "Direct line") reports the wrapper's font — check the span before treating it as a defect.
- Figma rounds text boxes up to whole pixels and draws strokes inside the box: buttons are exactly label + 48 wide, so the border comes off the padding. It also draws a fractional line height at a whole pixel (the 375 hero body's 24.3 renders as a 24 pitch), so match the rendered pitch in the render, not `lineHeightPx`.
- `npm run dev` serves `dist/` with browser-sync ghost mode off: its scroll and click sync between a phone and a desktop tab on the same page scrolled the phone to the desktop's proportional position on every adjustment, which read as the whole page jumping on the home accordion (2026-10-06). Test a phone with no other tab on the same page open, or the two will still fight through any sync.
- `npm run build`, then compare at 1640 with plain headless Chrome (`--window-size=1640,<tall> --screenshot`), and at phone/tablet widths with `node .qa/shot.mjs <file-url> <width> <height> <out.png> 1 [wait-ms]` (real device emulation; plain headless clamps to a minimum window width). `python .qa/slice.py` cuts tall shots into strips.
