# Claremont College cutup — rules (read by Claude + the Figma MCP)

Stack: plain **HTML** pages · Bootstrap 5.3 (CSS-variable themed) · **LESS** (ITCSS + BEM) · the `anim` system · build-time HTML partial includes (posthtml-include). Output in `dist/` is plain HTML + one CSS + one JS.

## Tokens + units
- Every design value lives in `src/assets/styles/01-settings/_tokens.less` as a `:root` custom property. Custom CSS uses `var(--…)` only; **no px anywhere** (rem, em, %, vw). The 8px scale (`--space-*`) drives mobile and tablet rhythm; at the design width components use the exact Figma value in rem with the px figure in a trailing comment (`5.3125rem; // 85`). Component-specific Figma measures are declared as local custom properties at the top of the block, with the px value in a trailing comment.
- Bootstrap is themed only through `--bs-*` in `_bootstrap-vars.less`; buttons through `--bs-btn-*` in `05-components/_buttons.less`.
- **The root font-size is a px table per breakpoint**, in `html` in `03-base/_base.less` — the one place px is allowed, because every rem resolves against it. Nothing else in the project may use px. 16 holds from 0 to the 1640 design width and is load-bearing there: the Figma audit at 1640, the 44 tap targets (`2.75rem`), the 16 form controls and the 12 text floor are all rem and verified at 16, so changing any value up to 1640 breaks them. Above it the whole design steps up together (18 at 1920, 21 at 2200, 24 at 2560) so a wide screen is not a small island. A px root ignores the reader's own browser font setting (browser zoom still works); switching the table to `%` — `100%` for 16, `112.5%` for 18, `131.25%` for 21, `150%` for 24 — renders identically and restores that. After any change here, re-run the Figma audit and `mobile-audit.mjs`: both must be unchanged, because both only ever see 16.
- **Escape fluid maths from LESS**: `~"clamp(1rem, 0.5rem + 2vw, 3rem)"`, `~"max(…)"`, `~"min(…)"`. Unescaped, LESS adds rem + vw into a wrong constant.
- Breakpoints are the LESS vars `@bp-sm … @bp-xxl` (px, matching Bootstrap's grid exactly), mobile-first `min-width` queries. `@upto-lg`, `@upto-md` and `@upto-xxl` are the `max-width` twins for redraws and for Figma measures that only exist at the design width; `@bp-design` (1640) is the frame itself.
- **A fixed Figma measure must still fit a 992 screen.** Where a value only works with the whole 1640 frame, it scales down with `clamp()` and returns to the exact Figma value by 1640 (the header logo, nav gap and link size from 992 to 1200; the pillar and link-column paddings), or the column caps it with container units (`container-type: inline-size` on the item, then `min(…, 20cqw)` for the pillar statement and `calc(100cqw * 475 / 302)` for the news card's height). Never a fixed height where copy can grow: the mosaic rows follow their photos' aspect ratios and the cards stretch, so a long paragraph on a narrow laptop grows the row instead of spilling out.
- Headings wrap naturally (no `text-wrap: balance`): Figma's line breaks are greedy.

## Markup
- `h1`–`h6` carry **no classes**; style through the parent block (`.pillars h3`, `.site-footer h2`).
- One section = one partial in `src/sections/` with a `@wagtail-block` comment. Shared, parametrised blocks take `locals='{…}'` (JSON in a single-quoted attribute: use typographic apostrophes, escape inner double quotes). Every local a partial reads must be passed, even as `""`. Page-specific list content lives in `src/sections/<page>/`.
- Icons are `<symbol>`s in `partials/icons.html`, used via `<svg class="icon"><use href="#icon-name">`, coloured by `currentColor`. The diagonal arrow symbol is 32 wide; list arrows carry `margin-right: -0.375rem` to land where Figma's 26 frame does.
- Images: WebP under `src/assets/images/<page>/`, always with `width`/`height` attributes and alt text.
- Animation only via `data-anim-*` (loops use `data-anim-group` on the parent). Reveal animations leave an inline `opacity` on the element, so state styles that touch opacity go on a child. `data-anim="sequence"` plays one staggered timeline over its `data-anim-item` descendants (the header drop, the hero quick links, the approach tabs and hotspots) and clears their inline styles when done, so those items keep their own hover transitions; an item may name its own preset (`data-anim-item="wipe-right"` on the open hotspot card). Rich text cannot mark its paragraphs, so a sequence wrapping CMS output takes `data-anim-items="children"` and its direct children become the items (the hero intro body). Sequences may nest: an item belongs to its nearest sequence ancestor (the phone accordion rows slide in from the right as one staggered sequence on `.tab-content`, around the hotspot sequences inside each pane; on desktop the rows are hidden, so that sequence has no items and does nothing). A sequence whose items sit side by side only on desktop takes `data-anim-mobile="each"` so each item reveals on its own where they stack (the pillar statements, the hero intro paragraphs — there with `data-anim-stagger="0"`, so on desktop they still enter together as one block); `data-anim-disable-mobile` skips it entirely (the hotspots). Scroll reveals play once the element's top reaches 85% of the viewport; `data-anim-start` overrides that in ScrollTrigger syntax for tall blocks whose pieces sit low (the hotspots use `top 45%`). A scroll reveal already in view at load follows the page entrance as its last step (it starts `entranceLead` before the entrance ends), so a short hero such as the news article's never lets the copy below beat the title. On phones a scroll step also waits for its section title, the nearest split before it in the same `main > *` block, so copy never beats its heading; the home page opts out with `data-anim-titles-first="off"` on `<main>` because its 375 frame is choreographed per block. `data-anim-tier="hero"` is the page entrance: one timeline on load, stepping through `data-anim-order` (header 0, title 1, then the rest), each step starting 0.4s before the previous one ends unless `data-anim-lead` says otherwise; `data-anim-order-mobile` replaces the order below 992 where the phone layout stacks things differently (the home quick links enter right after the title there, before the intro copy). Scroll-scrubbed steps (`data-anim="progress"`, or a reveal with `data-anim-scrub`) likewise take `data-anim-start-mobile`, `data-anim-end-mobile` and `data-anim-scrub-mobile` twins (the day-in-the-life steps scrub at 1.5 on desktop and 0.5 on phones, so they track the spine, which scrubs at 0.5). A scrubbed reveal triggers from its nearest `data-anim-trigger` ancestor, or else its parent, because its own box has already been moved by the preset's start state: give it an untransformed slot of its own (the Mina Wylie photo) or the trigger is wherever the parent happens to be, which on phones can be a whole section above it. Hero titles are `data-anim="split" data-anim-type="chars"` (the reference: characters rise 0.38em — 50 at the 131.6 desktop title, 23 at the 60 phone title — 0.3s each, 30ms apart) and section titles are `chars-soft` (0.4em: 14 at the 35 h2, 0.25s, 20ms apart, the whole run capped at 0.5s); both revert to the original markup when done, so kerning is exact at rest. The entrance waits for `document.fonts.ready` (800ms cap) so a split never measures the fallback face, and the split's boxes reset `text-indent` (the hero's indented line) so they do not indent again. The build-time search index gives headings without an `id` a slug, so a result can deep-link to its section. Banner photos use `.parallax-media(@travel)`; the inner hero uses the spare image Figma has below the frame (exact at rest).
- Page transition (`06-animation/_page-transition.less`: cross-document view transitions, `@view-transition { navigation: auto }`): the next page slides up over the page being left, which settles back and dims beneath it; a back step reverses it (the head script tags the transition `back` from `navigation.activation` on `pagereveal`). The old and new roots keep `mix-blend-mode: normal`, or the overlap washes out. The hero entrance is untouched but waits for the slide to land: the head script stores the transition's `finished` promise as `window.__pageArrival` (null at the first frame when there is none) and `Anim.init({ after })` holds the entrance on it, capped at 2s. `scripts/transition.js` only prefetches a page link on hover, focus or touch so the slide can start on the click. A browser without cross-document view transitions, and reduced motion, load as before; in-page jumps never transition, and neither does a `file://` preview (opaque origin), so shoot it over http.
- No inline styles. Data-driven positions (hotspots) use modifier classes that set `--x` / `--y`.
- Heading-left / copy-right rows are `row g-4 row-split` with two `col-lg-6`: Figma butts the two 620 columns together and lets the heading's own box leave the air, which only holds once the columns reach 620 at xxl, so `.row-split` keeps a 40 gutter up to 1300 and closes it to 0 by 1400 (`_bootstrap-vars.less`). Never `g-lg-0` on its own. A designed `<br>` in a heading that needs the whole 620 box is hidden with `@upto-xxl` (the news lead).
- Carousels that need real slider behaviour are Swiper (bundled from npm, core CSS inlined in `main.less`): a `data-slider` section holds a `.swiper` with `data-slider-start`, and its own `data-slider-prev/next` arrows (`scripts/slider.js`). Slides snap to the `.container` edge like the native scrollers (`data-slider-edge`, or `data-slider-edge="md"` to run full-bleed on phones and snap from tablets). `data-slider-below-lg` on the section builds the Swiper only below lg and tears it down above, so one list of items (one CMS block) is a CSS grid on desktop and a slider on phones (the pillars: `data-slider-per-view="1"`, arrows disabled at the ends); `data-slider-per-view-md="2"` shows two slides from md (the executives and the mosaic pairs on tablets).

Match those, not an interpretation of the desktop. Renders are cached in `.qa/figma/renders/`, `python .qa/mdump.py <node> [depth]` prints the frame-relative tree with type styles, and `node .qa/measure-m.mjs <url> <width> [selector]` lists the built page's section offsets to line up against it. Every other page is still an interpretation of 1640 — its mobile frame exists (`claremont welcome M` and friends on the same canvas) but has not been built. Likewise the frame stretches the hero button and the two footer buttons to the 335 column; the client asked for label-width buttons on phones, so no `.btn` ever takes `flex: 1 1 100%` or `width: 100%`. The frame also draws the phone footer left-aligned; the client asked for just the brand block centred, so below md the logo, the copy under it and the two buttons are centred and everything else keeps the frame's left alignment. - Blocks the designer **redrew** for phones (rather than reflowed) get one `@media @upto-lg` block at the end of their LESS file, so the desktop rules above stay untouched and the 1640 audit cannot move: the header, hero, approach, pillars, testimonials, feature banner, CTA and footer all have one. Everything else stays mobile-first `min-width`.
- **Tablets (768–991) keep the phone redraw's structure but not its phone-only measures.** Inside a redraw's `@upto-lg` block, the 375 frame's card sizes go under `@media @upto-md` and tablets fall back to the desktop card: the testimonials run the 412 cards from the container edge with the peeking one dimmed, the educators the 357 photo cards, the executives and mosaic two slides side by side, the stacked banners and the music photo a 3 : 2 crop from sm instead of the square, the quick links their long labels from md, and the home hero title wraps at `5.4em` so its three lines hold as the type grows. Nothing designed for phones changes below 768.
- Folded content (the approach accordion, its topics) collapses through a `grid-template-rows: 0fr → 1fr` transition, never `display: none`: the anim system only binds elements that have a box at load, so anything hidden with `display: none` never gets `is-revealed` and its `data-anim-item`s stay invisible when shown (`initApproachAccordion` also calls `Anim.add(pane)` on open). Check phone rules against desktop ones of higher specificity (`.approach .tab-pane .approach__overlay` sets `transition`); nest to outrank them.
- Phone crops of the home photos are `python .qa/fills-crop.py mobile` (`*-m.webp`), served through a `<picture>` whose `<source media="(min-width: 576px)">` carries the landscape desktop file: the square crops are for portrait phones only, and a tablet or a phone in landscape shows the landscape photo (the home hero at `max(514px, 67vw)` tall, its top edge as on desktop).
- Checked with `node .qa/mobile-audit.mjs <widths> [page …]` (overflow, tap targets under 44, text under 12, inputs under 16, oversized images). It must print no findings from 320 to 1600 beyond the `heavy` notices for pages that have no phone crop yet; the footer's fixed columns once overflowed at 1400–1560, so always include 1440.
- **One gutter everywhere**: `.container` is fluid up to the 1240 content width and every full-bleed block pads with `--container-gutter` (20 phone, 32 from md, 40 from lg, notch-aware through `env(safe-area-inset-*)`). Never reintroduce Bootstrap's fixed container widths.
- **Touch targets are 44 (`--tap-size`)**. Base styles are the touch size; the compact Figma size goes inside `@media @fine-lg` / `@fine-xl` (desktop width + a real mouse). Where the layout must not move, `.tap-area()` adds an invisible 44 hit area through `::before`; never on stacked links closer than 44 apart, and not on elements that already use `::before`. One exception: a text-link list the designer drew at a tight pitch (the phone footer's quick links and contact values) keeps that pitch under `data-tap-aa`, whose targets meet WCAG AA's 24 instead (`mobile-audit.mjs` accepts 24 inside it); the two stacked emails set `--tap-size: 1.5rem` on their hit areas so they do not overlap.
- Form controls are 16px on touch (iOS zooms the page below that); body copy is 16 on phones, 15 from md.
- Hover styling on controls that stay on screen (carousel arrows) sits inside `@media (hover: hover)`.
- Desktop-only measures (`max-width` for the zigzag timeline, fixed footer columns) start at the breakpoint that needs them, not before. The footer's 487 / 300 / 188 columns need the whole frame, so they are `fr` shares from xxl and fixed only from `@bp-design`.
- Hero images carry `fetchpriority="high"`; everything below the fold is `loading="lazy" decoding="async"`. Production CSS is minified by esbuild in `build.mjs`.

## QA
- **Never build a section from a guess.** Read its Figma nodes first (`python .qa/find.py <page-id> "<text>"` shows a text's box, style and parent frames; `.qa/extract.py <page-id>` dumps a page).
- `bash .qa/audit.sh summary|full [page …]` builds, measures each page at 1640 (`measure.mjs`) and compares with Figma (`compare.py` for sections + text runs, `compare-img.py` for photo boxes). A change is done when the page shows no `<<<` section flags and no text run off by more than ~3px. Expected noise: the two logos (Figma frame is wider than the artwork), `weight 400 vs 100` (Figma records the Argent CF Thin face as 100/250; the CSS asks for 400 and the `@font-face` range maps it onto Thin — the rendered face is correct), labels joined by `<br>`, and runs where Figma's own boxes disagree — the hero's x values (h1 198 / subtitle 201 / body 200) and the preparatory 4-up label row whose gaps are 406/416/406 against an even 410. `compare.py` matches a Figma text node to the widest measured run, so a node split across a wrapper and an inner span (enrolment's "Direct line") reports the wrapper's font — check the span before treating it as a defect.
- Figma rounds text boxes up to whole pixels and draws strokes inside the box: buttons are exactly label + 48 wide, so the border comes off the padding. It also draws a fractional line height at a whole pixel (the 375 hero body's 24.3 renders as a 24 pitch), so match the rendered pitch in the render, not `lineHeightPx`.
- `npm run build`, then compare at 1640 with plain headless Chrome (`--window-size=1640,<tall> --screenshot`), and at phone/tablet widths with `node .qa/shot.mjs <file-url> <width> <height> <out.png> 1 [wait-ms]` (real device emulation; plain headless clamps to a minimum window width). `python .qa/slice.py` cuts tall shots into strips. Laptop and landscape widths to check after a responsive change: 768, 820, 1024, 1180, 1280, 1366, 1440 and 667 × 375, 932 × 430.
- **Proving 1640 is untouched**: `git stash`, build, `measure.mjs` every page at 1640 into one folder, `git stash pop`, build, measure again into another, then `cmp` the JSON pairs. Identical files mean the desktop audit cannot have moved; that is the check to run after any change to a shared rule (breakpoints, `.row-split`, the header, footer or a redraw block).
- In a very tall test viewport every reveal fires in one batch, so late elements can still be mid-animation at capture time. That is a test artefact; raise the wait.
